# CLAUDE.md — Nordlys

Nordlys is a small offline native Windows app (.NET 10 + WPF) that teaches game development through **papers** (lecture-style Markdown readings) and **questions** (Khan Academy-style practice with hints, explanations, review scheduling and mastery levels). The app does **not** write lessons. Lessons are generated by Claude in a separate claude.ai chat using `generator-prompt.md`, copied as text, and imported. The app is a player and progress tracker. That split keeps it small, free (no API key, no network) and updatable without rebuilding: new content and new prompt rules are plain files.

The full original spec is in `HANDOFF.md`. Choices that differ from it are in `DECISIONS.md` (including why the app is native WPF rather than the Tauri/WebView app the handoff described). Ideas that are out of scope go in `IDEAS.md`, not in the code.

## The lesson format is the contract

The format is defined by `content/generator-prompt.md` (what Claude is told to write) and enforced by `desktop/Nordlys.Core/Lesson/Parser.cs` + `Validator.cs` (what the app accepts). Validator messages are part of the contract: Claude reads them in the error report. **Any format change must update all of these together, and bump `version`:**

1. `Nordlys.Core/Lesson/Types.cs`, `Parser.cs`, `Yaml.cs`
2. `Nordlys.Core/Lesson/Validator.cs`
3. `content/generator-prompt.md` (the FORMAT SPEC section and the example)
4. The sample lessons in `content/lessons/`
5. The tests in `desktop/Nordlys.Tests/` (bundled lessons must stay at 0 errors and 0 warnings)

YAML is resolved like js-yaml's core schema (`Yaml.cs`): plain `5` is a number, `"5"` is text. Keep it that way, or lessons that validated before will start failing.

## Design principles (these override taste)

1. **One primary action per screen.** Home screen = one big "Next" button.
2. **Zero ambiguity.** Every lesson shows "Done means: …" (the exact finish condition). Every button label says exactly what it does ("Check answer", not "Submit").
3. **No shame mechanics.** No streaks, no hearts/lives, no red "WRONG". A wrong answer shows **"Not yet"** in yellow, plus a hint option.
4. **Predictable layout.** Same structure every time. No surprise popups, no auto-playing anything.
5. **Low friction to resume.** App reopens exactly where he left off.
6. **Keyboard-first.** Everything doable without the mouse.
7. **Reduced motion respected.** Animations ≤150 ms; off entirely if Windows' animation effects are off or the setting is on.

Non-goals for v1: accounts, sync, telemetry, any network call except the update check (GitHub only, see below), calling an AI API, a database, gamification (XP, badges, streaks), a lesson editor.

## How to run

Needs the .NET 10 SDK (installed). Commands from `desktop/`:

```bash
dotnet build                                   # Core, App, Tests
dotnet test --project Nordlys.Tests            # 168 tests: parser, validator, checks, Leitner, mastery, next, storage, updates
dotnet run --project Nordlys.App               # the app, on the real data folder
dotnet run --project Nordlys.App -- --data C:\temp\nordlys-test   # on a throwaway data folder
dotnet publish Nordlys.App -c Release -r win-x64 --self-contained true -p:PublishReadyToRun=true -o publish\folder
& "$env:LOCALAPPDATA\tauri\NSIS\makensis.exe" /DVERSION=0.3.0 installer\nordlys.nsi   # -> publish\Nordlys-0.3.0-setup.exe
```

## Releasing an update

Raise `<Version>` in `desktop/Directory.Build.props` and push to main. `.github/workflows/release.yml` tests, builds and publishes GitHub release `v<version>` with `Nordlys-<v>-win-x64.zip`, its `.sha256` and the installer (it does nothing if that release already exists). Installed copies find it (once a day at start, or Settings → Check for updates), download it in the background, verify the SHA-256 and swap the app folder on "Restart to update". Code: `Nordlys.Core/Updates.cs` (check, download, safe extract, `Updater.Apply` with rollback) and `Nordlys.App/Shell/UpdateService.cs` (state, restart flow via `--apply-update`). Only an installed copy (with `uninstall.exe` next to it) updates itself; `dotnet run` builds never do.

`global.json` opts into the Microsoft Testing Platform (needed for `dotnet test` on .NET 10 with xUnit v3).

## Code map

- `Nordlys.Core/` (no UI): `Lesson/` format · `Progress/` progress.json, Leitner, mastery, next lesson, learner context · `Quiz/` attempt engine and answer checks · `Storage/` `IStore` (atomic `FileStore`, `MemoryStore`) · `AppState.cs` shared state, first-run seeding, coalesced saves, prompt building · `WindowGeometry.cs` marquee maths.
- `Nordlys.App/` (WPF): `MainWindow.cs` chrome (WindowChrome, Snap Layouts, placement, F11, keyboard) · `Shell/` navigation, context menus, marquee resize, Win32 interop · `Rendering/` Markdig → FlowDocument (WpfMath, SharpVectors, highlighter, glossary) · `Quiz/` question card and answer controls · `Views/` one file per screen · `Theme/` Nord palette as dynamic resources and control styles · `UI/` builders and Fluent icon glyphs.
- Views refer to the shared state as `Data` (from `Views/Routes.cs`): inside `Nordlys.App`, the name `App` is the WPF application class.
- Context menus: `Menus.Attach(element, e => entries)` builds a menu when it opens. The innermost region wins; text boxes inside a region get their edit actions merged in. Return null to let an outer region decide. Unavailable actions are passed with a null action (shown disabled) or left out.
- `scripts/native-ui.ps1` + `native-menus.ps1`: drive the app through UI Automation on a throwaway data folder, open context menus with the Menu key, capture the window. `measure-desktop.ps1` measures a build; `test-window-state.ps1` checks window memory.
- `content/` bundled defaults, embedded into Nordlys.Core and copied to the data folder on first run.

## Where user data lives

`%APPDATA%\app.nordlys\` (the same folder the earlier Tauri version used): `lessons/`, `progress.json`, `settings.json`, `curriculum.json`, `generator-prompt.md`, `backups/progress-YYYY-MM-DD.json` (last 14 kept), `crash.log` if something went wrong.

First run copies `content/` into the data folder. Later runs never overwrite the user's copies. Settings has "Reset generator prompt to default". Never run tests or scripts against this folder: use `--data`.
