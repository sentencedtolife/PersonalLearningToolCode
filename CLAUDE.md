# CLAUDE.md — Nordlys

Nordlys is a small offline desktop app (Tauri 2 + vanilla TypeScript + Vite) that teaches game development through **papers** (lecture-style Markdown readings) and **questions** (Khan Academy-style practice with hints, explanations, review scheduling and mastery levels). The app does **not** write lessons. Lessons are generated by Claude in a separate claude.ai chat using `generator-prompt.md`, copied as text, and imported. The app is a player and progress tracker. That split keeps it small, free (no API key, no network) and updatable without rebuilding: new content and new prompt rules are plain files.

The full original spec is in `HANDOFF.md`. Choices that differ from it are in `DECISIONS.md`. Ideas that are out of scope go in `IDEAS.md`, not in the code.

## The lesson format is the contract

The format is defined by `content/generator-prompt.md` (what Claude is told to write) and enforced by `src/lesson/parse.ts` + `src/lesson/validate.ts` (what the app accepts). **Any format change must update all of these together, and bump `version`:**

1. `src/lesson/parse.ts` and `src/lesson/types.ts`
2. `src/lesson/validate.ts`
3. `content/generator-prompt.md` (the FORMAT SPEC section and the example)
4. The sample lessons in `content/lessons/`
5. The tests in `tests/` (bundled lessons must stay at 0 errors and 0 warnings)

## Design principles (these override taste)

1. **One primary action per screen.** Home screen = one big "Next" button.
2. **Zero ambiguity.** Every lesson shows "Done means: …" (the exact finish condition). Every button label says exactly what it does ("Check answer", not "Submit").
3. **No shame mechanics.** No streaks, no hearts/lives, no red "WRONG". A wrong answer shows **"Not yet"** in yellow, plus a hint option.
4. **Predictable layout.** Same structure every time. No surprise popups, no auto-playing anything.
5. **Low friction to resume.** App reopens exactly where he left off.
6. **Keyboard-first.** Everything doable without the mouse.
7. **Reduced motion respected.** Animations ≤150 ms; off entirely if the OS prefers reduced motion or the setting is off.

Non-goals for v1: accounts, sync, telemetry, any network call, calling an AI API, a front-end framework, a database, gamification (XP, badges, streaks), a lesson editor.

## How to run

Needs Node LTS, Rust (rustup) and the MSVC C++ build tools (Visual Studio 2026 Community is installed on Elliott's PC and works).

```bash
npm install          # once
npm run dev          # web version in a browser at http://localhost:1420 (uses localStorage)
npm run app          # desktop window (tauri dev)
npm test             # vitest: parser, validator, question checks, Leitner, mastery, next-lesson
npm run build        # type-check + web build into dist/
npm run release      # installer: src-tauri/target/release/bundle/nsis/*.exe
```

## Code map

- `src/main.ts` boot, routes, global keyboard handler · `src/router.ts` hash router
- `src/store/` `Store` interface; `TauriStore` (fs plugin, AppData) and `BrowserStore` (localStorage)
- `src/lesson/` parse → validate → render (Markdown, KaTeX, highlight.js, SVG figures, DOMPurify)
- `src/quiz/` question engine (`engine.ts`) and one file per question type in `types/` (pure `check` + DOM `render`)
- `src/progress/` progress.json, Leitner scheduling, mastery levels, learner-context block, next-lesson picker
- `src/views/` one file per screen · `src/ui/` header bar, sidebar, small components
- `content/` bundled defaults copied to the data folder on first run (curriculum, generator prompt, 3 sample lessons)

## Where user data lives

- Desktop: `%APPDATA%\app.nordlys\` (Tauri `BaseDirectory.AppData`): `lessons/`, `progress.json`, `settings.json`, `curriculum.json`, `generator-prompt.md`, `backups/progress-YYYY-MM-DD.json` (last 14 kept).
- Browser (`npm run dev`): the same paths as `localStorage` keys prefixed `nordlys:/`.

First run copies `content/` into the data folder. Later runs never overwrite the user's copies. Settings has "Reset generator prompt to default".
